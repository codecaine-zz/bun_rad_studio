# Changelog

All notable changes. Version 1.4.2 is the eleventh release (1.0.0, 1.1.0, 1.2.0, 1.2.1, 1.2.2, 1.3.0, 1.3.1, 1.3.2, 1.4.0 and 1.4.1 came first); changes made after a release are listed under **Unreleased**. Each entry points to the record of what was observed and how it was checked in [discrepancies](docs/documentation-maintenance/discrepancies.md). History before 13 October 2026 is only in git.

## 1.4.2 (17 October 2026)

### Added

- **Find File Manager tools without scrolling.** Filter apps by name, description or group in Tools and Split views, open matches with the keyboard, and clear the filter without leaving the current tool.
- **Terminal selection and clipboard controls.** Copy, Paste and Select all buttons and a right-click menu work with terminal output and scrollback. Shell Ctrl+C and Ctrl+A keep their original behavior.
- **Local lyric-video and MP3 music archives.** Package original local videos and extracted 128 kbps MP3 songs with readable filenames and CC BY 4.0 attribution, without downloading YouTube playlists.
- **Tutorial source examples.** Include the SimpleGUI click-event example and the terminal-short production script.

### Improved

- **Download folders open inside File Manager.** Open folder uses the built-in Files view and selects completed downloads; System file manager remains a separate option.
- **Predictable text entry.** Inputs disable spelling corrections and saved-entry suggestions, with Select all, Clear text and clipboard editing actions. Opening the editing menu does not commit an inline rename.
- **macOS release refresh.** Rebuild the standalone File Manager, full suite and desktop app bundles for Apple silicon and Intel.

### Verification (Windows release)

- **Windows terminal and File Manager updates.** Verified right-click Copy/Paste and Select all, toolbar paste, Ctrl+V, Ctrl+Shift+C/A, and unchanged Ctrl+C interruption against a real PowerShell ConPTY session on Windows ARM64 with x64 GUI emulation. Targeted terminal, UI and release checks passed (180 checks, with optional/platform-specific cases skipped), and typechecking reported no errors.
- **Windows downloads.** Built the full suite and standalone File Manager for x64, x64-baseline and ARM64. The ARM64 standalone archive passed a packaged-server startup and terminal clipboard resource smoke test; this is not a claim of manual testing on native x64 hardware.

## 1.4.1 (17 October 2026)

### Added

- **File Manager: local lyrics in Quick Look and More info.** Show embedded MP3, FLAC, Ogg, MP4 and ffprobe lyric tags, matching local `.lrc` and `.txt` files, and video subtitle text. No online lookup or transcription is used.
- **Free music download bundles.** The Codecaine playlist is available as source audio, full-length MP3s and individual chapter tracks under CC BY 4.0, separately from the MIT application downloads.

### Improved

- **File Manager theme shortcut help.** The fixed Option/Alt + `[` and `]` shortcuts for cycling through all themes are now shown in the shortcut list.

### Fixed

- **Linux desktop shortcuts in standalone and full-suite downloads.** Installers no longer insert a stray backtick before executable paths on GNU/Linux. Rerun `sh install.sh` from the extracted folder to repair an existing menu entry.
- **Standalone File Manager startup diagnostics.** Launchers preserve the application's exit code and consistently write errors to `~/.bun_rad_studio/file-manager-startup.log`.
- **CI regression fixtures.** File Manager tests account for macOS Command shortcuts and canonical temporary paths, and Showcase checks each app's image without assuming a fixed featured-image count.

### Fixed (Windows refresh, 17 October 2026)

- **Local lyrics load in the media player.** Matching `.lrc` and `.txt` files now use an authenticated, size-limited text preview instead of being rejected with HTTP 415. Verified embedded and local lyrics, source switching and the L shortcut on Windows, including paths with spaces, mixed-case extensions and CRLF text.
- **Music-pack builds on Windows.** The optional builder uses built-in PowerShell ZIP support rather than requiring Unix `zip` and `unzip`; `yt-dlp` and FFmpeg remain required.
- **Release builds use the current Bun executable.** A stale compiled runtime on `PATH` can no longer silently replace the compiler and leave Windows launchers missing.

## 1.3.1 (16 October 2026)

### Fixed

- **All Linux desktop downloads: opt-in Ubuntu AppArmor sandbox fix.** `sh install.sh --apparmor` validates and loads an executable-specific user-namespace permission using sudo, fixing WebKit's `bwrap` / `dbus-proxy` startup crash under Ubuntu 24.04+'s namespace restrictions without disabling AppArmor or the WebKit sandbox. Covers every desktop app and child studio through the full suite's shared runtime on ARM64, x64 and x64-baseline, plus the standalone File Manager. CLI-only musl downloads are unchanged. Rerun after moving the folder; `sh install.sh --uninstall --apparmor` removes the profile. [Linux release instructions](docs/developer/releasing.md#linux-sandbox-permissions).
- **File Manager: no more silent native-window startup failure.** A failed window creation is detected instead of reporting success and exiting. Packaged native libraries load only when a window is needed, so missing desktop dependencies no longer prevent server mode or browser fallback from starting. The fallback now invokes the default browser, and standalone Windows/Linux downloads save startup output and errors to `~/.bun_rad_studio/file-manager-startup.log` (`%USERPROFILE%` on Windows). Windows instructions now include the native DLL's Visual C++ x64 runtime dependency. [Startup and troubleshooting](docs/userguides/43_file_manager.md#start-it).

### Verification

- The executable-specific AppArmor fix was confirmed working on an Ubuntu 24.04 ARM64 desktop. Installer tests cover all 73 desktop launchers on ARM64, x64 and x64-baseline, including real AppArmor profile syntax validation when the parser is available. This is not a claim that every app's UI was manually tested on those CPUs.
- Linux ARM64 File Manager: rebuilt archive tested in a Linux container with a visible X11 window, HTTP responses, missing-native-library browser-opener invocation, no-display fallback, and headless mode without the native library. Windows executables were cross-compiled but not run on Windows; the new regression tests also exercise a compiled host launcher and persistent error logging.

### Added

Only Latin and Greek letters lose marks; Cyrillic, Japanese, Korean and Indian scripts are left alone. The file keeps its encoding, byte-order mark and line endings; a file that is not UTF-8/UTF-16 must be told its encoding (*Read it as*) because guessing would damage it; characters that the encoding can't hold stop the run with nothing written. In the Code tab, *Tools* menu and command palette: **Remove accents**, **Join letters and accents**, **Split letters and accents**, on the selection or the whole file. Tests: `tests/file_manager_diacritics.test.ts`.
- **Code tab: Convert text, about seventy built-in conversions** for the selection or the whole file (🔤 Convert button, Tools → Convert text…): case styles (camel, Pascal, snake, CONSTANT, kebab, Train, dot, path, Sentence, swap), clean-up (trim, blank lines, spaces, join/wrap lines, curly quotes, invisible/control/non-ASCII characters, emoji, HTML tags, look-alikes, accents), lines (numbers, bullets, quotes, comma and JSON lists, sort by length, shuffle, reverse), encode and escape (Base64, hex, binary, URL, HTML, JSON, `\u`, regex, shell, ROT13, Morse, slug), extract (links, e-mail, numbers, IPv4, hashtags, words) and dates/numbers (Unix timestamps, thousands separators). Saved as `shortcuts` in the settings; the server drops invalid or clashing entries, including from a hand-edited file. Menus, tooltips and Help follow the keys in force. New `shortcuts.js` (rules, tested), `keymap.js`, `shortcutsDialog.js`; the file list's key handler is now table-driven. Tests: `tests/file_manager_shortcuts.test.ts` and page tests in `file_manager_views.test.ts`.

### Fixed

- **MySQL and PostgreSQL Studio: sidebar row counts are real.** They used the database's estimates (MySQL caches `TABLE_ROWS` for a day, PostgreSQL's `reltuples` is stale until a vacuum), so a table could show rows and open empty, or show none and open full. Tables up to 100,000 rows are now counted for real; bigger ones keep the estimate.

- **File Manager: TOML dates and times became `{}` when converted** (Bun now returns them as Temporal objects); they are kept as text (`2024-01-15T10:30:00Z`). Found by checking the built-in converters against `Bun.TOML`, `Bun.YAML` and `Bun.JSON5` (`file_manager_convert_oracle.test.ts`).
- **File Manager: JSON5 reading** now accepts `\x41` and other single-character escapes, line continuations, letters of any language and `\u0061` escapes in unquoted keys, and refuses numbers with a leading zero (`0777`) instead of reading them as 777, as JSON5 and Bun do.
- **File Manager: a stray "null" next to Properties.** Selecting a file without a "Edit in Code editor" button (a PDF, picture, zip, sound...) showed the word *null* after the buttons in the Details panel, because a missing part was passed to `append`, which prints it. The same slip was in the Dev tab's TODO list when nothing was cut off. `tests/file_manager_info_panel.test.ts` checks every kind of selection.
- **Linux themes:** list boxes, sliders and pickers could be unreadable in dark themes, and switching themes while a window was open left old inline surface colours (unreadable text on every OS) ([D-047](docs/documentation-maintenance/discrepancies.md#d-047)).
- `bun start` crashed at launch ([D-001](docs/documentation-maintenance/discrepancies.md#d-001)); the designer page's script was cut short so the page did nothing, and its Import, Keys and Audit dialogs could never appear ([D-016](docs/documentation-maintenance/discrepancies.md#d-016), [D-017](docs/documentation-maintenance/discrepancies.md#d-017)).
- Exported projects did not parse ([D-011](docs/documentation-maintenance/discrepancies.md#d-011)); Import could corrupt the open form ([D-018](docs/documentation-maintenance/discrepancies.md#d-018)).
- Run only worked from the project folder ([D-023](docs/documentation-maintenance/discrepancies.md#d-023)); Frogger, Snake and Tetris only started from the repository root ([D-038](docs/documentation-maintenance/discrepancies.md#d-038)). Run now keeps the preview's output in `.rad_preview/preview.log` and shows failures in the status bar ([D-040](docs/documentation-maintenance/discrepancies.md#d-040)).
